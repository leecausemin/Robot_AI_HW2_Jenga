ROS2 Communication
• 메시지(Message): 노드(Node)와 노드(Node) 사이에 주고 받는 데이터
- 토픽(Topic): 비동기식 단방향 메시지 송수신 방식 (Publish-Subscribe 통신)
- 서비스(Service): 동기/비동기식 양방향 메시지 송수신 방식 (Request-Response 통신)
- 액션(Action): 비동기식 양방향 메시지 송수신 방식 (Goal-Feedback-Result 형태의 비동기 통신)

Nodes in ROS2
• 우리가 개발하고자 하는 로봇 시스템은 여러 개의 Node들이 함께 작동하는 시스템으로 구성되며, node들 간의 통신은
아래 그림과 같이 이루어진다.

ROS2 Topic
• Topic은 Node가 Message(data)를 교환하는 Pub-Sub 형태의 Communication channel 이다.
• Publisher Node는 Topic에 Message를 던져주고 (publish) Subscriber Node는 Topic으로 Message들 받는다 (subscribe).

ROS2 Topic
• 하나의 Node는 여러 개의 Topic들에 Message를 게시할 수 있고, 동시에 여러 개의 Topic들을 구독할 수 있다.

ROS2 Topic 구성 요소
• Topic Name: Node들이 어떤 데이터를 주고 받는지 구분하기 위한 Topic의 이름

예) /cmd_vel (로봇 속도 명령), /joint_states (로봇 관절 상태 정보)
• Topic Type (Message Type): Topic을 통해 전달되는 데이터의 형식(구조)에 대한 규약 (일종의 IDL)
Publisher와 Subscriber는 같은 Message Type을 사용해야 함

예) geometry_msgs/msg/Twist (/cmd_vel topic이 주고 받는 message의 데이터 구조)
• Message Definition: Message Type을 실제로 정의한 데이터 구조

여러 개의 field로 구성되며, 각 field는 built-in type 또는 다른 message type으로 이루어짐
예) Twist message 내부에 포함된 Vector3 구조
Vector3 linear
float64 x
float64 y
float64 z

(Vector3라는 ROS2 message type)
(float64라는 ROS2 built-in type)
ROS2 Common Interfaces (Message types) : https://github.com/ros2/common_interfaces
Built-in types: https://docs.ros.org/en/humble/Concepts/Basic/About-Interfaces.html#field-types

ROS2 Interfaces
• ROS2에서는 서로 다른 개발자나 시스템이 만든 노드 간
통신은 다음 3가지 유형의 “Interfaces”를 통해 이루어지며,
간단한 IDL((Interface Definition Language)를 이용해 기술됨.
.msg files
describe topic message

.srv files
describe a service

.action files
describe actions

int32 my_int
string my_string
string move
--bool success
int32 secs
--string status
--string feedback

• IDL로 정의된 Description은 ROS에서 여러 다양한 대상
언어로 노드 간 통신과 관련된 소스 코드를 자동으로 생성함

ROS2 Service
• Service는 Request-and-Response model에 기반한다. (Topic은 Pub-Sub Model)
• Topic은 data stream을 publish하고 지속적으로 update되지만, Service는 Client가 호출할 때만 data가 제공된다.

ROS2 Service
• 동일한 service를 사용하는 service client는 여러 개가 있을 수 있지만
해당 service를 처리하는 service server는 단 하나만 존재한다.

Program Service Client with Python

def send_request(self):
# send the request
self.request.r = 255
self.request.g = 0
self.request.b = 0
self.request.width = 10
self.request.off = 0
# future check if service has finished the request or not.
self.future = self.client.call_async(self.request)

Program Service Client with Python
set_pen_client.py
def main(args=None):
rclpy.init(args=args)
client = SetPenClient()
client.send_request()
while rclpy.ok():
rclpy.spin_once(client)
if client.future.done():
try:
response = client.future.result()
client.get_logger().info("The pen is changes.")
except Exception as e:
client.get_logger().info("Service call failed: {}".format(e))
break
client.destroy_node()
rclpy.shutdown()

def callback(self, request, response):
self.get_logger().info("Service is called: [{}]".format(request.data))
on_off = request.data
if type(on_off) is bool:
if on_off:
response.message = "ON"
else:
response.message = "OFF"
response.success = True
else:
response.success = False
response.message = "Fail: Request should be bool"
return response
