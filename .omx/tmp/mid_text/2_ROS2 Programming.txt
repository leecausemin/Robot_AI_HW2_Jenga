ROS (Robot Operating System)
Robot Operating System (ROS) is an open-source robotics middleware suite. Although ROS is not
an operating system (OS) but a set of software frameworks for robot software development, it
provides services designed for a heterogeneous computer cluster such as hardware abstraction,
low-level device control, implementation of commonly used functionality, message-passing
between processes, and package management.

Setup ROS2 Build System
• Build System은 SW 개발에서 개발자가 프로그램 언어로 작성한 소스코드를 컴퓨터에서 실행 가능한 프로그램으로
만드는 일련의 과정을 자동화하는 도구 및 전체 프로세스이다. (예: CMake, Maven, MSBuild, Ant, python setuptools, Poetry 등)
• ROS 2는 CMake 기반의 ament라는 Build System을 사용하며, colcon을 Build를 위한 command line tool로 사용
- ament: 기존 CMake 기반의 C++뿐만 아니라 Python 패키지도 함께 ROS 2 환경 내에서 일관된 방식으로 빌드 및
설치될 수 있도록 하는 규칙과 절차 (ament_cmake, ament_python)
- colcon: 여러 개의 ROS 2 패키지를 적절한 순서로 빌드하고, 의존성 관리, 테스트, 패키징, 배포 등을 위한 Build tool

ROS 주요 용어 정리
• 노드(Node): 최소 단위의 실행 가능한 프로세스 (프로그램)
(예) 경로계획 노드, 영상처리 노드, 모터제어 노드 …

[참고] 실행파일(Executable): ROS2 Runtime에서 호출되는 실행 가능한 프로그램 (C++ 또는 Python)
하나의 executable에 여러 개의 node가 포함될 수 있음

ros2 run <package> <executable>
• 패키지(Package): 노드들을 공유 및 배포하기 위한 묶음
• 메시지(Message): 노드(Node)와 노드(Node) 사이에 주고 받는 데이터
- 토픽(Topic): 비동기식 단방향 메시지 송수신 방식 (Publisher 노드와 Subscriber 노드 간 통신)
- 서비스(Service): 동기식 양방향 메시지 송수신 방식 (Client 노드와 Server 노드 간 통신)
- 액션(Action): 비동기식 양방향 메시지 송수신 방식 (Client 노드와 Server 노드 간 비동기 통신)

Node
• ROS 시스템에서 독립적으로 실행되는 단위 프로그램을 Node라고 한다.
• 하나의 package 내 다양한 복수의 node들이 구성된다.
(Node 예)
하나의 로봇 시스템을 여러 개의 Node로 분할하여 구현

- Node for reading data from a sensor
- Node for receiving operator controls from a joystick
- Node for sending control signals to a motor
- Node for displaying a visualization to an operator
- Node for computing trajectory to follow

• ROS2 node는 다른 node들과 ROS communication middleware를 사용하여 서로 데이터를 주고 받는다.

Package
• Package란 ROS2 program에 관련된 모든 프로그램 코드, 설정 파일, 데이터 등을 묶어주는 소프트웨어 기본 단위이다.

• 일반적으로 하나의 package는 하나의 기능을 수행한다. 예를 들어, Sensor package, Navigation package,
Manipulation Package 등으로 만들어질 수 있다.

$ ros2 run <package> <executable>

Workspace
• Workspace는 ROS2 programming을 위한 일종의 작업공간으로 개발자가 ROS package를 만들고 build하고
관리하기 위한 최상위 directory이다.
• Workspace에 다양한 package들을 만들고, 각 package에는 다양한 node들을 만든다.
• Create workspace
$ mkdir -p ~/${workspace}/src
$ cd ~/${workspace}/
$ colcon build
(예) $ export workspace=~/Dev/lecture/ros2/basics_ws
• 정상적으로 build되었다면 ${workspace} 하위 폴더에
src, build, install, log라는 폴더가 생성된다
- build 폴더 : 패키지의 컴파일 과정에서 생성되는 중간 파일들을 저장. 소스 코드의
컴파일에 필요한 모든 파일이 이곳에 위치
- install 폴더: 빌드 과정이 성공적으로 완료된 후, 실행 가능한 파일, 라이브러리,
그리고 패키지가 사용하는 리소스 파일들이 이곳에 설치.
- Log 폴더: 빌드 과정에서 발생하는 모든 로그를 저장합니다. 빌드 중에 문제가
발생했을 때, 이 로그를 통해 문제의 원인을 파악

Setup Package: package.xml
• package.xml: 우리가 만든 my_first_pkg package에 대한 meta 정보와 dependencies 정보가 들어있다.
- 패키지 기본 정보 (이름, 버전, 유지보수자, 라이선스 등)
- 의존성 관리 (dependencies 선언)
우리가 수정해야할 라인: 이 package가 참조할 다른 package들을 포함한 dependencies를 여기에 추가

<depend>rclpy</depend>
<depend>sensor_msgs</depend>
...
- 빌드 도구 및 환경 설정 (CMake, Colcon과 연동)
<buildtool_depend>ament_cmake</buildtool_depend>
<buildtool_depend>ament_python</buildtool_depend>

우리가 수정해야할 라인: 이 package 내 실행가능한 Executable들을 terminal에서 실행할 때 쓰는 script를 지정
