Motion Planning & Control
• Robot Motion Planning
특정 목표(Goal)를 달성하기 위해 미래에 수행할 일련의 동작이나 경로를 생성하는 과정

- 핵심역할: 언제(When), 어디로(Where), 어떻게(How) 움직일 것인가를 미리 계획
- 입력: 현재상태, 목표상태 및 환경정보 (obstacles, constraints)
- 출력: 미래의 Time-parameterized motion plan / Trajectory
(joint-space trajectory, Cartesian path, action sequence 등)

• Robot Control
Planning에서 생성된 계획을 실제 로봇 하드웨어가 정확하게 따라가도록 만드는 과정
- 핵심역할: 계획과 실제 사이의 오차를 보정하여 실시간 실행 (How to execute)
- 입력: 현재상태 (Feedback) 및 목표 (Setpoint, Reference, Trajectory 등)
- 출력: 구동기에 즉시 전달되는 고주파(High-frequency) 제어명령
(position, velocity, force/torque, 또는 impedance 제어값 등)

Path Planning
• 로봇이 이동할 수 있는 공간을 정의하고, 그 안에서 충돌없이 이동할 경로(path)를 찾는 것
- Workspace: 로봇이 물리적으로 존재하는 공간(3D)
- Configuration space: joint 변수 공간(𝑞-space)
- Collision-free: 장애물과 충돌하지 않는 𝑞들의 집합
• Input: Initial configuration, Goal configuration, 환경정보, Constraints 등
• Output: 로봇 움직임에 대한 collision-free path 𝑞(𝑠).
• 어디로 갈지만 정하고 얼마나 빨리/어떤 힘으로는 아직 없음.
- path 𝑞(𝑠)는 geometry 문제이고, 아직 물리(time/torque)는 고려되지 않음

Path Planning Algorithms
• PRM (Probabilistic Roadmap Method)
- (Data Sampling) 로봇의 configuration space로부터
random sample을 취한 후, 이들이 free space 상에 있는지
알아보고 Collision-free space 내의 node들을 샘플링한다.
- (Graph Modeling) 샘플링된 노드들을 연결하고, 이 연결이
Collision-free space 상에 있으면 이들을 모두 연결하여 하
나의 Graph로 만든다.
- (Path Finding) 시작 노드(Start configuration)와 끝 노드
(goal configuration)를 추가한 후 graph search algorithm
을 이용하여 시작점과 끝점을 가장 유효하게 연결하는 path
를 결정한다.

Trajectory Planning with Dynamics
• 속도/가속도가 주어질 때, 로봇이 실제로 움직이기 위해 어떤 힘(토크)이 필요한지를 이해하고 계산
(주어진 trajectory가 dynamics 및 torque limit을 만족하며 실제로 실행 가능한지를 평가)
𝑀 𝑞 𝑞̈ + 𝑏 𝑞, 𝑞̇ + 𝑔 𝑞 = 𝜏 + 𝐽 (𝑞) 𝐹

관절의 가속도를 만들기 위해 필요한 운동방정식

𝑀 𝑞 𝑞̈ : Inertia (관성)
𝑏 𝑞, 𝑞̇ : Coriolis/Centrifugal (속도효과)
𝑔 𝑞 : Gravity (중력)
𝜏: Actuator torque (외부에서 관절에 가해지는 토크)
𝐽 (𝑞) 𝐹 : Contact Force (환경과의 접촉에 따른 힘)
Robot Dynamics Lecture Notes, Robotic Systems Lab, ETH Zurich, 2017

• Input: trajectory 𝑞 𝑡 , 𝑞̇ 𝑡 , 𝑞̈ (𝑡), robot dynamics model
• Output: Torque: τ(t)
• 같은 trajectory라도 필요한 torque가 커질 수 있고, torque limit을 넘으면 실행 불가능해짐

Low-level Control
• 계획한 trajectory를 실제 로봇이 오차 없이 잘 따라가게 만드는 것
• 실제로는 planning이 아무리 좋아도 모델 오차, 마찰, 센서 노이즈, 외란 등으로 feedback control이 필수
• 대표적인 controller:
- PD/PID (joint space)
- gravity compensation
- computed torque (inverse dynamics + PD)
• Planning이 reference를 만든다면, control은 tracking을 안정화하는 것으로 볼 수 있음

Robot Hardware vs. Controllers
• 로봇은 다양한 HW (sensors, actuators)로 구성되어 있으며, 이들은 서로 각각 다른 control algorithm으로 구동된다.
• 비슷해 보이는 2개의 로봇이 있지만 이들은 통신방식도 다르고, 제어방식도 다를 수 있다.
즉, 한 로봇의 motor는 serial 방식으로 연결되어 있고, 다른 로봇은 CAN 방식으로 연결되어 있으며, 하나는 위치제어를
제어하고 다른 하나는 토크제어를 할 수 있다.

URDF(xacro) 에 ros2_control 설정
• 사용 중인 Controller type에 따른 HW Interface 지정
（urdf/cnuarm_ros2_control.xacro）

- gazebo_ros2_control/GazeboSystem
. libgazebo_ros2_control.so 내부의 핵심 클래스

. Gazebo에서 ROS2 컨트롤러와 로봇을 연결하는 플러그인
. 실제 HW 인터페이스 구현을 담당함

- command_interface: send data
- state_interface: read data
• Type of interfaces
- position
- velocity
- effort

<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">
<xacro:macro name="cnuarm_ros2_control" params="name prefix">
<ros2_control name="${name}" type="system">
<hardware>
<plugin>gazebo_ros2_control/GazeboSystem</plugin>
</hardware>
<joint name="${prefix}joint1">
<command_interface name="position">
<param name="min">-1</param>
<param name="max">1</param>
</command_interface>
<state_interface name="position"/>
</joint>
<joint name="${prefix}joint2">
<command_interface name="position">
<param name="min">-1</param>
<param name="max">1</param>
</command_interface>
<state_interface name="position"/>
</joint>
</ros2_control>
</xacro:macro>
</robot>
